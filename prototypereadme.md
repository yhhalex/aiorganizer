# AI Organizer Prototype README

This file describes the prototype version of AI Organizer. The prototype is not expected to implement the full AI document organizer yet. Its job is to show the intended user flow, frontend screens, and local database behavior for the first build.

The prototype should focus on:

1. Storage
2. Folder Addition

Everything should run locally. Do not depend on external APIs, hosted databases, cloud storage, external AI services, or remote vector databases for this prototype.

---

## Prototype Goal

The goal is to prove that users can add documents or notes, store their records locally, create folders, and connect stored items to folders through the frontend.

The prototype can use placeholder logic where needed. For example, folder suggestions can be based on filenames or manually selected by the user instead of generated by AI.

This means the first version does not need:

- real AI classification
- semantic search
- embeddings
- cloud sync
- production file parsing
- external library APIs
- complete backend automation

It only needs to make the planned storage and folder workflows visible and testable.

---

## 1. Storage

Storage is the local system that keeps track of all documents, notes, folders, and folder assignments.

### Storage Requirements

The prototype should allow the app to:

- create local item records
- store item metadata
- store or reference local files
- save pasted note text
- save folders
- link items to folders
- reload saved data when the app restarts
- show whether an item is pending, stored, assigned, or needs review

No data should need to leave the user's machine.

---

### Local Database Options

Use a local database depending on the prototype environment:

- SQLite if the app has a desktop shell or local backend
- IndexedDB if the prototype is browser-only
- Local JSON only if this is a very early mockup

SQLite is the preferred mental model for this README because it makes the database relationships clear.

---

### Core Tables

#### `folders`

Stores each folder shown in the frontend.

| Field | Purpose |
| --- | --- |
| `id` | Unique folder ID |
| `name` | Folder display name |
| `description` | Optional folder description |
| `created_at` | When the folder was created |
| `updated_at` | When the folder was last changed |

Example folder:

```text
id: folder_001
name: Machine Learning
description: Class notes, slides, and references related to ML
```

#### `items`

Stores documents, notes, or saved local records.

| Field | Purpose |
| --- | --- |
| `id` | Unique item ID |
| `type` | `file`, `note`, or `link-placeholder` |
| `title` | Display title |
| `source_path` | Local file path, if the item is a file |
| `content_text` | Pasted note text or mock extracted text |
| `status` | `pending`, `stored`, `assigned`, or `needs_review` |
| `created_at` | When the item was added |
| `updated_at` | When the item was last changed |

Example item:

```text
id: item_001
type: file
title: machine-learning-slides.pdf
source_path: /local/path/machine-learning-slides.pdf
status: stored
```

#### `folder_items`

Connects items to folders.

One item can appear in more than one folder.

| Field | Purpose |
| --- | --- |
| `folder_id` | Folder that contains the item |
| `item_id` | Item assigned to the folder |
| `assignment_type` | `manual`, `suggested`, or `mock-auto` |
| `created_at` | When the item was assigned |

Example relationship:

```text
folder_id: folder_001
item_id: item_001
assignment_type: suggested
```

#### `folder_suggestions`

Stores folder suggestions that the user has not accepted yet.

| Field | Purpose |
| --- | --- |
| `id` | Unique suggestion ID |
| `item_id` | Item being reviewed |
| `folder_id` | Existing folder suggestion, if one exists |
| `suggested_folder_name` | New folder name, if suggesting a new folder |
| `reason` | Short explanation shown in the UI |
| `status` | `pending`, `accepted`, or `dismissed` |

Example suggestion:

```text
item_id: item_002
suggested_folder_name: Databases
reason: Filename contains "database"
status: pending
```

## Storage Flow

When a user adds an item:

1. The frontend creates an item with `status = pending`.
2. The app stores the file reference or note text locally.
3. The item changes to `status = stored`.
4. The app checks for a basic folder match.
5. If a match exists, the app creates a pending folder suggestion.
6. If no match exists, the item moves to `needs_review`.
7. The user accepts a suggestion or manually chooses a folder.
8. The app creates a `folder_items` row.
9. The item appears inside the selected folder.

For the prototype, the matching step can use simple local rules:

| Rule | Suggestion |
| --- | --- |
| Filename includes `database` | Suggest `Databases` |
| Filename includes `machine-learning` or `ml` | Suggest `Machine Learning` |
| Filename includes `regression` | Suggest `Regression` |
| No match | Mark as `needs_review` |

## 2. Folder Addition

Folder Addition is the frontend and database workflow for creating folders and assigning items to them.

### Folder Addition Requirements

The prototype should support:

- creating a folder manually
- showing folders in a sidebar or folder list
- showing item counts per folder
- opening a folder detail view
- assigning an item to an existing folder
- creating a new folder from a suggestion
- keeping empty folders visible
- allowing one item to belong to multiple folders

---

### Manual Folder Creation Flow

1. User clicks `Add Folder`.
2. A form opens.
3. User enters a folder name.
4. User optionally enters a description.
5. App validates that the name is not empty.
6. App writes a row to `folders`.
7. Frontend refreshes the folder list.
8. New folder appears with `0` items.

Expected UI state after creation:

```text
Folders
- Machine Learning (0)
- Databases (0)
- Regression (0)
```

---

### Assign Item to Existing Folder Flow

1. User adds `machine-learning-slides.pdf`.
2. App creates an item record.
3. App suggests the existing folder `Machine Learning`.
4. User clicks `Accept`.
5. App writes a row to `folder_items`.
6. Folder count updates from `0` to `1`.
7. Item appears in the `Machine Learning` folder detail view.

Expected UI state:

```text
Machine Learning

Items
- machine-learning-slides.pdf
```

---

### Create Folder From Suggestion Flow

1. User adds `database-normalization-notes.md`.
2. App does not find a matching existing folder.
3. App suggests a new folder named `Databases`.
4. User clicks `Create Folder`.
5. App creates a row in `folders`.
6. App creates a row in `folder_items`.
7. The item appears inside the new folder.

Expected UI state:

```text
Folders
- Databases (1)

Databases

Items
- database-normalization-notes.md
```

## Frontend Prototype Screens

### Dashboard

Shows a simple overview:

- number of stored items
- number of folders
- number of items needing review
- recent items

### Folder Sidebar

Shows:

- folder list
- item counts
- selected folder
- `Add Folder` action

### Folder Detail

Shows:

- folder name
- description
- list of assigned items
- empty state when the folder has no items

### Add Item Panel

Allows the user to:

- select a local file
- paste text as a note
- enter or edit the item title
- save the item

### Review Inbox

Shows items that need confirmation.

Each row should show:

- item title
- item type
- suggested folder, if available
- reason for suggestion
- `Accept`
- `Choose Folder`
- `Create New Folder`
- `Dismiss`

---

## Prototype Success Criteria

The prototype is successful when the user can:

- create a folder
- add a file record
- add a note record
- save records locally
- restart the app and still see saved records
- see folder counts
- assign an item to a folder
- create a folder from a suggestion
- view folder contents
- review unassigned items

The prototype does not need to be smart yet. It needs to make the correct future behavior obvious.

---

## Later Implementation Ideas

After the local prototype works, future versions can add:

- real document text extraction
- local full-text search
- duplicate detection
- local embeddings
- AI-generated folder suggestions
- natural-language answers with source references
- optional sync or backup

These should be added only after the local storage and folder workflows are stable.
